# Follow API (Gravel & Pavement Scout check-ins)

Base URL: `https://follow.doubleperspective.com`. JSON in and out (`Content-Type: application/json`).
App calls use `Authorization: Bearer <token>` from registration. Times are milliseconds since epoch.

## Rider (this phone)
| Call | Body | Answer |
|---|---|---|
| `POST /api/riders` | `{name, lang: "en"\|"fr"}` | `{riderId, token}` (keep the token in encrypted app storage; it is never shown again) |
| `PUT /api/riders/me` | `{name?, lang?, fcmToken?}` | `{ok, limits}` |
| `DELETE /api/riders/me` | — | Deletes everything about this phone (rides, positions, links, follows) |

`limits` = `{pro, intervals, maxFollowers, fullPath}`. The free limits are a server switch (`settings.free_limits = {"enforced": true|false}`, default off), so early access can end without an app update.

## Ride
| Call | Body | Notes |
|---|---|---|
| `POST /api/rides` | `{intervalMin: 15\|30\|60, expectedReturn?, lat, lon, battery?}` | Ends any open ride. Answer `{rideId, intervalMin, limits}` |
| `POST /api/rides/:id/checkins` | `{points: [{t, lat, lon, kind?, note?}], tracks?: [encodedPolyline], battery?}` | Up to 200 points; send queued dead-zone points in one call when signal returns. `kind`: `move` (default), `stop`, `ok`, `battery` |
| `POST /api/rides/:id/pause` | `{kind: "fuel"\|"restaurant"\|"camp"\|"pause", until, lat, lon}` | Alerts wait until `until` (5 min – 24 h). Cleared by the next `move` |
| `POST /api/rides/:id/alert` | `{lat, lon}` | "Everything OK?" got no answer: followers are alerted now |
| `POST /api/rides/:id/end` | `{lat, lon}` | "Home safe" |

Server-side alerts (cron every 5 min): "no news" 2 intervals + 15 min after the last check-in (or the end of a pause); alarm 30 min after `expectedReturn`, otherwise 2 h (15/30 min) or 3 h (60 min). A check-in after an alert sends "back in touch".

## Followers
| Call | Notes |
|---|---|
| `POST /api/links` `{label?, permanent?}` | Private link `{linkId, url, permanent}`. Not permanent = this ride only, works until 12 h after the ride ends |
| `GET /api/links`, `DELETE /api/links/:id` | Cancelling removes everyone who joined through it (app and browsers) at once |
| `POST /api/follow/:token` | In-app follower: the follower's phone redeems the link token from the URL |
| `GET /api/following`, `DELETE /api/following/:id` | Follower screen data (same shape as the web view below) |
| `GET /api/followers`, `DELETE /api/followers/:id` | The rider's list of in-app followers |

Web page: `GET /f/<token>`; data `GET /api/f/<token>`: `{riderName, lang, now, ride: {state, last, battery, expectedReturn, pauseUntil, pauseKind, ...}, points}`. `state`: `riding`, `paused`, `no_news`, `alarm`, `no_answer`, `ended`, `idle`.

## Notifications
- Browsers: Web Push without payload (VAPID keys are generated by the Worker and kept in D1); the service worker fetches the status and shows it.
- App: FCM data messages `{type: start|no_news|alarm|no_answer|back|end, followId, riderId, riderName, rideId, at}`; the app builds the text in the follower's language. Needs the `FCM_SERVICE_ACCOUNT` secret (Firebase service-account JSON); until it is set, app followers get no push.

## Privacy
- Positions are deleted 7 days after a ride ends; rides never ended are closed 48 h after their last check-in.
- Tokens are stored only as SHA-256. No IP addresses or follower identities are stored.
- Pages send `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex`.

Road-following path: `tracks` are Google encoded polylines (precision 5) of the recorded track since the previous check-in, one per check-in; stored one row per segment and shown only when `fullPath` (Pro).
